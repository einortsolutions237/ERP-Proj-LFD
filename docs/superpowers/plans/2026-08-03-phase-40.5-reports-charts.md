# Phase 40.5 (Reports Creative Polish — New Charts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add five real, working data visualizations to the three Reports pages (Sales ×3, Inventory ×1, P&L ×1), using two new shared chart components, visualizing only data the report-building functions already compute. Zero changes to `src/lib/reports/*.ts`, zero new business logic.

**Architecture:** Two new `'use client'` recharts components in `src/components/reports/`, matching `src/components/dashboard/RevenueTrendChart.tsx`'s existing established pattern exactly (hardcoded hex mirroring live CSS custom properties, `ResponsiveContainer`, a `Tooltip`). Each report page maps its own already-computed aggregate into a shared `{ label, value }[]` shape inline and renders the appropriate chart inside its own `Card`.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS, `recharts` (already a project dependency — no new package). The `dataviz` skill's mark specs, interaction rules, and palette validator govern every chart in this plan.

**Design spec:** `docs/superpowers/specs/2026-08-03-phase-40.5-reports-charts-design.md` — read this first for the full reasoning behind every decision below (chart-type selection, color assignment, why no time-series chart, why P&L gets no headline-number chart).

## Global Constraints

- Zero changes to `src/lib/reports/{sales,inventory,pnl}.ts` or either report API route — every chart visualizes data these functions already return today.
- Zero changes to any existing table, the CSV export logic, or any capability check (`requireCapability`, `hasEffectiveCapability`) anywhere in this phase.
- No dark-mode chart variant — this app has no dark mode (confirmed: zero `prefers-color-scheme`/dark-token entries in `globals.css`).
- Colors are exactly two already-locked tokens' literal hex values, read directly from `globals.css` — `info` (`#2563eb`) for Sales/Inventory charts, `brass` (`#c08a28`) for P&L's expense chart. No new color is introduced anywhere. **(Corrected during Task 1: the design originally specified `marine` for Sales/Inventory, but `dataviz`'s `validate_palette.js` found it fails the chroma floor on its own — 0.07, reads as gray when used as a filled chart bar. `info` passes every check cleanly. See the design spec's correction note and the SDD ledger for the full validator output.)**
- Every chart is single-series (sequential, one hue) — no legend is added anywhere, per `dataviz`'s own rule that a single series needs no legend box.
- No direct per-bar value labels (`LabelList`) — every chart sits directly above its own complete, already-existing table, so per-bar labels would be redundant; readers get exact values from the Y-axis ticks, the hover tooltip, or the table. This is a deliberate reading of `dataviz`'s "never a number on every point" rule, not an oversight.
- `topSellers` and `expensesByCategory` charts are capped to the top 5 entries; `byBranch` and `byPaymentMethod` charts show every entry (both are small, bounded sets by this app's own architecture/data model).
- `impeccable` used in **audit mode only** in this phase's own audit task — no new aesthetic decision beyond what's in the approved design spec. `frontend-design` and `ui-ux-pro-max` are consulted only as passive reference (per the series spec's own skill-mapping for this phase), not invoked as a separate task.
- Review tier: Sonnet-tier review is sufficient for Tasks 1-3 (no Firestore transaction, no money/inventory write — these are pure rendering-layer additions over already-computed, read-only aggregates). Task 4 (P&L) is also Sonnet-tier for the same reason.

- [ ] **Step 2: Create `CategoryBarChart.tsx`**

```tsx
'use client'
import { useEffect, useState } from 'react'
import { BarChart, Bar, XAxis, YAxis, CartesianGrid, Tooltip, ResponsiveContainer } from 'recharts'

// Recharts renders raw SVG and does not consume Tailwind utility classes for
// stroke/fill — these hex values are the literal values of this app's
// --color-mist/--color-slate tokens (src/app/globals.css) and must be updated
// here too if those tokens ever change. Matches the identical, already-reviewed
// exception documented in src/components/dashboard/RevenueTrendChart.tsx.
const MIST = '#e2e8f0'
const SLATE = '#475569'

export interface BarChartDatum {
  label: string
  value: number
}

export default function CategoryBarChart({
  data,
  color,
  valueLabel,
}: {
  data: BarChartDatum[]
  color: string
  valueLabel: string
}) {
  const [reducedMotion, setReducedMotion] = useState(false)
  useEffect(() => {
    const mq = window.matchMedia('(prefers-reduced-motion: reduce)')
    setReducedMotion(mq.matches)
  }, [])

  return (
    <div className="h-56 w-full">
      <ResponsiveContainer width="100%" height="100%">
        <BarChart data={data} margin={{ top: 8, right: 8, left: 0, bottom: 0 }}>
          <CartesianGrid stroke={MIST} vertical={false} />
          <XAxis dataKey="label" stroke={SLATE} tick={{ fontSize: 11 }} />
          <YAxis
            stroke={SLATE}
            tick={{ fontSize: 11 }}
            width={56}
            tickFormatter={(value: number) => value.toLocaleString()}
          />
          <Tooltip
            formatter={(value: unknown): [string, string] => [
              typeof value === 'number' ? value.toLocaleString() : String(value),
              valueLabel,
            ]}
            contentStyle={{ borderRadius: 12, borderColor: MIST, fontSize: 12 }}
          />
          <Bar dataKey="value" fill={color} radius={[4, 4, 0, 0]} maxBarSize={24} isAnimationActive={!reducedMotion} />
        </BarChart>
      </ResponsiveContainer>
    </div>
  )
}
```

This implements `dataviz`'s mark spec exactly: `maxBarSize={24}` caps bar thickness at ≤24px, `radius={[4, 4, 0, 0]}` gives a 4px rounded data-end (top) with a square baseline (bottom), `CartesianGrid` renders hairline/solid/recessive gridlines using the app's own `mist` token, the `Tooltip` provides the hover layer, and `isAnimationActive={!reducedMotion}` is a real `prefers-reduced-motion` check (via `window.matchMedia`, not assumed) — `recharts`' own bar-entrance animation is JS-driven and does **not** automatically respect the CSS media query this app otherwise relies on globally, so this component checks it explicitly. No legend (single series). No per-bar value labels (values live in the Y-axis ticks, the tooltip, and the table below).

- [ ] **Step 3: Create `RankedBarChart.tsx`**

```tsx
'use client'
import { useEffect, useState } from 'react'
import { BarChart, Bar, XAxis, YAxis, CartesianGrid, Tooltip, ResponsiveContainer } from 'recharts'

// See CategoryBarChart.tsx for why these are hardcoded hex rather than
// Tailwind classes — identical reasoning, same tokens.
const MIST = '#e2e8f0'
const SLATE = '#475569'

export interface BarChartDatum {
  label: string
  value: number
}

export default function RankedBarChart({
  data,
  color,
  valueLabel,
}: {
  data: BarChartDatum[]
  color: string
  valueLabel: string
}) {
  const [reducedMotion, setReducedMotion] = useState(false)
  useEffect(() => {
    const mq = window.matchMedia('(prefers-reduced-motion: reduce)')
    setReducedMotion(mq.matches)
  }, [])

  return (
    <div className="w-full" style={{ height: Math.max(data.length * 40, 120) }}>
      <ResponsiveContainer width="100%" height="100%">
        <BarChart data={data} layout="vertical" margin={{ top: 8, right: 24, left: 8, bottom: 0 }}>
          <CartesianGrid stroke={MIST} horizontal={false} />
          <XAxis
            type="number"
            stroke={SLATE}
            tick={{ fontSize: 11 }}
            tickFormatter={(value: number) => value.toLocaleString()}
          />
          <YAxis type="category" dataKey="label" stroke={SLATE} tick={{ fontSize: 11 }} width={140} />
          <Tooltip
            formatter={(value: unknown): [string, string] => [
              typeof value === 'number' ? value.toLocaleString() : String(value),
              valueLabel,
            ]}
            contentStyle={{ borderRadius: 12, borderColor: MIST, fontSize: 12 }}
          />
          <Bar dataKey="value" fill={color} radius={[0, 4, 4, 0]} maxBarSize={24} isAnimationActive={!reducedMotion} />
        </BarChart>
      </ResponsiveContainer>
    </div>
  )
}
```

Note: in `recharts`, `layout="vertical"` on `<BarChart>` means the **bars render horizontally** (category axis vertical, value axis horizontal) — this is `recharts`' own naming (it refers to the axis arrangement, not the bar direction). `radius={[0, 4, 4, 0]}` gives a 4px rounded data-end on the right (where the bar terminates) with a square baseline on the left, the horizontal-bar equivalent of `CategoryBarChart`'s top-rounded/bottom-square spec. Container height scales with row count (`data.length * 40`, minimum 120px) since this component always renders a small, bounded list (≤5 rows per this phase's usage).
