## Design tokens — the foundation (Task 1)

- `--radius-card: 1rem` — used by Card primitive's default variant; replaces the prior hardcoded `rounded-2xl` approach

- `--radius-badge: 9999px` — full-circle radius for Badge in its pill-shaped presentation

## The 6 UI primitives (Tasks 2–7)

### Button (Task 2)

**File**: `src/components/ui/Button.tsx`

**API**: 
- Variants: `primary` (default), `secondary`, `ghost`, `danger`, `success` — each a distinct visual treatment with `disabled` state variant
- Icon mode: boolean `icon` prop for icon-only buttons (disables text spacing)
- Loading state: boolean `loading` prop internally uses a spinner component, with `disabled` automatically set when loading
- Destructures `type='button'` from `...rest` before spread to prevent accidental type overrides

**Rationale**: A single, composable component replacing scattered button patterns across the app; the loading state replaces text-swap patterns from POS (Task 9 standardizes this across Checkout).

### Card (Task 3)

**File**: `src/components/ui/Card.tsx`

**API**:
- Variants: `default` (rounded-2xl/border-mist/shadow-card via --radius-card/--shadow-card tokens), `nested` (minimal border, no shadow, for nested context)
- `hoverable` prop: adds `hover:shadow-card-hover` for interactive cards
- No internal `bg-*` classes — background is caller's responsibility, preserving flexibility for light/dark/colored contexts

**Rationale**: The default variant is a byte-for-byte visual no-op vs. the prior hardcoded `rounded-2xl border border-mist shadow-card` pattern (reviewed and independently confirmed), but centralizes the definition so the shared radius/shadow tokens control the look everywhere.

### Badge (Task 4)

**File**: `src/components/ui/Badge.tsx`

**API**:
- Tones: `success`, `warning`, `error`, `info`, `neutral` (default) — each pair of text/background using existing app palette at `/10` opacity
- Reuses `--radius-badge: 9999px` for pill shape
- Supports optional children for label text

**Rationale**: Consolidates the five out-of-stock/low-stock/waiting/active/neutral visual states that previously used inline Tailwind; no new colors invented.

### Alert (Task 5)

**File**: `src/components/ui/Alert.tsx`

**API**:
- Modes: `boxed` (default), `inline` — boxed is full-width with padding/border/background; inline is minimal with just left-border/text-color
- Tones: `success`, `warning`, `error`, `info` — one fewer than Badge, since alerts don't use `neutral`
- Appends `className` rather than replacing; the tone classes are always applied

**Rationale**: Gives offline sync and permission-denied messages (Phase 38's Task 4) a consistent, reusable treatment.

### PageHeader (Task 6)

**File**: `src/components/ui/PageHeader.tsx`

**API**:
- Required prop: `title` (string) — rendered with exactly `font-display text-xl font-semibold tracking-tight text-ink`
- Optional props: `description` (string), `actions` (ReactNode, typically buttons), `filters` (ReactNode, a control row)
- Semantically uses `<header>` with an `<h1>` for the title

**Rationale**: Eliminates repeated header markup (previously `<h1>` directly in screen components) and enforces the canonical heading hierarchy; every screen from Dashboard to Stock to Seminars now gets the same H1 treatment structurally rather than by convention.

### StatSummary (Task 7)

**File**: `src/components/ui/StatSummary.tsx`

**API**:
- Required props: `count` (ReactNode, typically a number), `label` (string)
- Optional prop: `tone` (default: `ink`) — one of `ink`, `danger`, `warning`, `info` (StatTone union)
- Renders as a simple count+label line with optional color tone

**Naming correction found during planning**: The spec assumed a KPI-card shape comparable to "large stat tiles" — the real code inspection revealed the Dashboard's 5 widgets all repeat a simple count+tone+label line (Total Sales: [number], Low Stock Items: [number], etc.), so the primitive was built to match that simple shape, not over-engineered as a complex card variant.
