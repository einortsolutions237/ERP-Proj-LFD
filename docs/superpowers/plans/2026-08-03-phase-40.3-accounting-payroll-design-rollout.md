# Phase 40.3 (Accounting + Payroll Design-Primitive Rollout) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the Accounting (Expenses) and Payroll modules onto the shared design primitives (`PageHeader`/`Button`/`FormSection`), closing the 5th and 6th of TD-6's seven modules simultaneously, with zero business-logic, data-fetching, or capability-check changes.

**Architecture:** Pure rendering-layer re-parenting — swap existing hand-rolled markup for the equivalent shared primitive from `src/components/ui/`, matching the mechanical, zero-color/font-change discipline every prior design-rollout phase (10, 21, 22, 27, 28, 33, 34, 40, 40.1, 40.2) has used. `Alert` is already correctly in place in both forms (from Phase 38.5's earlier sweep) and needs no change.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS. Primitives already exist at `src/components/ui/{PageHeader,Button,FormSection}.tsx` — read, not modified.

## Scope clarification (resolved ambiguity, confirmed before writing this plan)

The series spec's Background section describes TD-6's module list loosely as "Accounting (Expenses / P&L)" and "Reports (Sales / Inventory / P&L)" — mentioning P&L in both places. Its own **Phase Breakdown table is more specific and is the authoritative source**: row 40.3 is "Accounting + Payroll" (no P&L mentioned) and row 40.4 is "Reports — mechanical primitive rollout (Sales, Inventory, P&L; **4 pages total**)," explicitly counting P&L as one of Reports' four pages. `src/app/(dashboard)/reports/pnl/page.tsx` lives under the `reports/` route, not a separate Accounting route — confirming it belongs to Phase 40.4, not this phase. **This plan therefore excludes `reports/pnl/page.tsx` entirely.** Phase 40.3's Accounting scope is the `expenses/` route only.

## Global Constraints

- Zero color/font/token changes — the one accepted exception is `PageHeader`'s `tracking-tight`, an already-established precedent (Phase 38.6, reused in Phase 40.2).
- No business-logic, data-fetching, or capability-check change anywhere in this phase — `requireCapability`, `hasEffectiveCapability`, `queryExpenses`, `queryPayrollRecords`, and both API routes are out of scope.
- Field order and visual field sequence must not change — `FormSection` wraps existing fields in their existing top-to-bottom order; no field is moved, renamed, or reordered relative to its neighbors.
- `impeccable` used in **audit mode only** — a consistency/accessibility spot-check, not a new aesthetic decision. `frontend-design` is **not used** in this phase.
- Review tier: Sonnet-tier review is sufficient — this phase touches no Firestore transaction and no money/inventory write (the write paths themselves, `api/expenses/route.ts` and `api/payroll/route.ts`, are not touched at all).
- Adding `id`/`htmlFor` pairs to form fields that currently lack them (see Task 2 and Task 4) is done incidentally while rewriting those exact JSX blocks for the `FormSection` wrap — matching the established convention already used by `StaffForm.tsx` — not a separate scope expansion, since every field block touched is already being fully rewritten for this phase's own purpose.

### Deliberate exclusions (confirmed during planning, hold throughout implementation and audit)

1. **`AttachReceiptForm.tsx`'s "Attach receipt" button** (`shrink-0 rounded-lg border border-mist px-2 py-1 text-xs text-ink transition-colors hover:bg-mist/40 disabled:opacity-50`) — a `text-xs` bordered micro-button. `Button` has no `text-xs` size option. Matches the identical exclusion category Phase 40.1 named for its own per-row micro-buttons ("Order lab test," "Attach scan," etc.) — this is in fact the *same* attach-scan pattern reused for expense receipts. Stays raw.
2. **Both table wrappers** (`expenses/page.tsx`'s and `payroll/page.tsx`'s `overflow-hidden rounded-2xl border border-mist bg-surface shadow-[var(--shadow-card)]` divs) — shape-matches a table wrapper, not `Card`. Matches the established "table wrappers stay hand-rolled" precedent (Stock/Products/Sales Log/Roles/Seminars all left theirs raw for the same reason).
3. **`expenses/page.tsx`'s receipt-link list** (`text-marine underline` anchors) — the established colored-text-link pattern, same exclusion category as every prior phase's Edit/Delete/View links.
4. **Empty-state text** ("No expenses recorded yet." / "No payroll records yet.") — plain loading/empty text, not an `Alert` candidate, matching the established convention that simple empty states stay raw across the whole app.
5. **`Card` is not used anywhere in this module** — no existing block matches `Card`'s bordered/shadowed/padded shape outside the two excluded table wrappers above.
6. **`Badge`/`StatSummary` are not used anywhere in this module** — no status pill or count/stat to migrate. Matches Phase 40's own precedent that not every primitive applies to every module.
7. **`DownloadCsvButton`** (used in `expenses/page.tsx`) is a pre-existing, unrelated component (not one of the six TD-6 primitives) — untouched.
