## Final whole-branch review

Dispatched on the most capable available model. Zero Critical findings. Two real findings, both fixed in one wave and independently re-verified:

- **Important**: `docs/tech-debt.md`'s TD-8 entry said "fifteen call sites," but this phase's two new `Button` submit buttons (in `ExpenseForm.tsx` and `PayrollForm.tsx`) were never added to that count — the plan itself had incorrectly asserted TD-8 was unaffected. Fixed: count bumped to seventeen (independently confirmed via `grep -c 'loading={' -r src/` summing to 17), both files added to the enumerated list.
- **Minor, with a real usability consequence**: three fields (`ExpenseForm.tsx`'s Amount, `PayrollForm.tsx`'s Staff-member and Gross-amount) were each wrapped alone in their own `FormSection`, rendering at half-width on desktop with an empty adjacent grid cell — a pure loss with no benefit. The concrete failure case: Payroll's Gross-amount placeholder ("Leave blank to use the staff member's base salary") — the only UI text explaining the field is optional — visibly truncated at half-width. Fixed: all three unwrapped to plain `<div>`s; the two genuine two-field pairs (`ExpenseForm.tsx`'s Date+Category, `PayrollForm.tsx`'s Pay-period-start+end) were left untouched.

This is a real example of the whole-branch review catching something no per-task review could — Task 2 and Task 4's reviewers each correctly verified their own file matched its own brief, but neither could see that the same "single-child `FormSection`" pattern, applied independently in two different forms, produced a layout regression only visible when reasoning about the rendered result rather than the diff.
