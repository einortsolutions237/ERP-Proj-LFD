# Phase 38.1 — Design System Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small internal design-token layer and primitives library (Button, Card, Badge, Alert, PageHeader, StatSummary), and prove them by migrating the Dashboard and POS/Checkout screens onto them — with zero business-logic, API, Firestore, or permission changes.

**Architecture:** Additive CSS custom properties in `src/app/globals.css` (radius + shadow scale only — no new colors, no new type-scale tokens; heading hierarchy is achieved by the primitives consistently applying one Tailwind class combination, not by new CSS variables). Six new presentational components under `src/components/ui/`, each a thin wrapper over the exact Tailwind classes already used somewhere in the app today. Two proof screens (Dashboard, POS/Checkout) are migrated onto these primitives; every other screen is untouched and deferred to Phase 38.2+.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS v4 (`@theme inline` in `globals.css`, no `tailwind.config.*`), Vitest (`environment: 'node'`, `tests/**/*.test.ts` only).

## Global Constraints

- No new npm dependencies (no `clsx`, no `tailwind-merge`, no icon library, no component library). Every primitive is hand-written JSX + template-string Tailwind classes.
- No new test-rendering infrastructure (no jsdom, no React Testing Library) — per the approved spec, primitives are verified via TypeScript strictness + `npm run build` + visual screenshot review, not rendered unit tests. The one exception is Task 1's token-presence test, which is plain Node file-reading (fits the existing `.test.ts`/`environment: 'node'` setup with zero new tooling).
- No API route, Firestore rule, Cloud Function, or permission-constant file may be touched by any task in this plan.
- Every existing color token (`marine`, `brass`, `mist`, `slate`, `success`, `danger`, `warning`, `info`, `ink`, `paper`, `surface`) keeps its current value. Only new radius/shadow tokens are added.
- **Where a current screen's ad hoc classes differ slightly from the primitive's one canonical class set (e.g., a button missing `text-sm`, a badge count-pill styled solid instead of translucent), the migration deliberately normalizes to the canonical set.** This is Phase 38.1's actual purpose — eliminating exactly this kind of drift — not an accidental regression. Every such normalization is called out explicitly in the task it happens in, and confirmed acceptable during Task 10's visual review.
- Two specific existing patterns are explicitly **excluded** from the Button primitive in this phase because they are functionally selectable list rows, not action buttons, and forcing them into `variant="primary/secondary/ghost/danger/success"` would misrepresent them: the product/service catalog-picker rows in `CheckoutForm.tsx` and the customer-picker result rows in the same file. Both are candidates for the `Table`/list primitive explicitly deferred to Phase 38.2 — leave them exactly as they are in this phase.
- The notification-count pill inside `QueueStatusIndicator.tsx`'s toggle button (`bg-danger px-1.5 py-0.5 text-xs text-paper`, solid fill) is a distinct "counter" visual pattern, not a semantic status `Badge` — it is intentionally left unmigrated. Note it as a `Badge` "counter" variant candidate for 38.2 if the pattern recurs elsewhere.

Consumed by Tasks 8 and 9.

- [ ] **Step 1: Write the component**

Create `src/components/ui/Button.tsx`:

```tsx
import type { ButtonHTMLAttributes, ReactNode } from 'react'

export type ButtonVariant = 'primary' | 'secondary' | 'ghost' | 'danger' | 'success'

const VARIANT_CLASSES: Record<ButtonVariant, string> = {
  primary: 'bg-marine text-paper hover:bg-marine/90',
  secondary: 'border border-mist text-ink hover:border-marine hover:bg-mist',
  ghost: 'text-ink hover:bg-mist',
  danger: 'border border-mist text-danger hover:border-danger hover:bg-danger/10',
  success: 'bg-success text-paper hover:bg-success/90',
}

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: ButtonVariant
  icon?: boolean
  loading?: boolean
  children?: ReactNode
}

function LoadingSpinner() {
  return (
    <svg className="h-4 w-4 animate-spin" viewBox="0 0 24 24" fill="none" aria-hidden="true">
      <circle cx="12" cy="12" r="9" stroke="currentColor" strokeWidth="2.5" strokeOpacity="0.25" />
      <path d="M21 12a9 9 0 0 0-9-9" stroke="currentColor" strokeWidth="2.5" strokeLinecap="round" />
    </svg>
  )
}

export default function Button({
  variant = 'primary',
  icon = false,
  loading = false,
  disabled,
  type = 'button',
  className = '',
  children,
  ...rest
}: ButtonProps) {
  const sizeClasses = icon
    ? 'flex min-h-11 min-w-11 shrink-0 items-center justify-center'
    : 'inline-flex min-h-11 items-center justify-center gap-2 px-3 py-2.5'

  return (
    <button
      type={type}
      disabled={disabled || loading}
      className={`rounded-[var(--radius-control)] text-sm font-medium transition-colors duration-200 disabled:pointer-events-none disabled:opacity-50 ${sizeClasses} ${VARIANT_CLASSES[variant]} ${className}`}
      {...rest}
    >
      {loading ? <LoadingSpinner /> : children}
    </button>
  )
}
```

Note the `type = 'button'` default is destructured out of `rest` explicitly — spreading `{...rest}` after an inline `type={...}` attribute would silently override it back to `undefined` whenever the caller doesn't pass `type`, which drops the button back to the HTML-default `type="submit"`. Destructuring it out avoids that.

**Interfaces:**

- Produces: `export default function Card(props: CardProps)`, `export type CardVariant = 'default' | 'nested'`, where `CardProps` extends `HTMLAttributes<HTMLDivElement>` with `variant?: CardVariant`, `hoverable?: boolean`. Consumed by Task 8 (`DashboardCard.tsx`) and Task 9 (`QueueStatusIndicator.tsx`'s popover).

- [ ] **Step 1: Write the component**

Create `src/components/ui/Card.tsx`:

```tsx
import type { HTMLAttributes, ReactNode } from 'react'

export type CardVariant = 'default' | 'nested'

// Background is deliberately not part of these classes — callers supply their
// own bg-* utility via `className`. Tailwind's generated stylesheet orders
// utilities of equal specificity by its own internal rule order, not by the
// order classes appear in a JSX className string, so two competing bg-*
// classes on one element would have an unpredictable winner. Keeping Card
// itself background-free avoids that entirely.
const VARIANT_CLASSES: Record<CardVariant, string> = {
  default: 'border border-mist shadow-[var(--shadow-card)]',
  nested: 'border border-mist/70',
}

interface CardProps extends HTMLAttributes<HTMLDivElement> {
  variant?: CardVariant
  hoverable?: boolean
  children?: ReactNode
}

export default function Card({
  variant = 'default',
  hoverable = false,
  className = '',
  children,
  ...rest
}: CardProps) {
  return (
    <div
      className={`rounded-[var(--radius-card)] p-4 ${VARIANT_CLASSES[variant]} ${
        hoverable ? 'transition-shadow duration-200 hover:shadow-[var(--shadow-card-hover)]' : ''
      } ${className}`}
      {...rest}
    >
      {children}
    </div>
  )
}
```

```tsx
import type { ReactNode } from 'react'

export type AlertTone = 'success' | 'warning' | 'error' | 'info'

const BOX_CLASSES: Record<AlertTone, string> = {
  success: 'border-success bg-success/10 text-success',
  warning: 'border-warning bg-warning/10 text-warning',
  error: 'border-danger bg-danger/10 text-danger',
  info: 'border-info bg-info/10 text-info',
}

const TEXT_CLASSES: Record<AlertTone, string> = {
  success: 'text-success',
  warning: 'text-warning',
  error: 'text-danger',
  info: 'text-info',
}

interface AlertProps {
  tone?: AlertTone
  inline?: boolean
  className?: string
  children: ReactNode
}

export default function Alert({ tone = 'info', inline = false, className = '', children }: AlertProps) {
  if (inline) {
    return (
      <p role="alert" className={`text-sm ${TEXT_CLASSES[tone]} ${className}`}>
        {children}
      </p>
    )
  }
  return (
    <div role="alert" className={`rounded-[var(--radius-control)] border px-3 py-2 text-sm ${BOX_CLASSES[tone]} ${className}`}>
      {children}
    </div>
  )
}
```
