`ConversationList.tsx` was reviewed and left untouched — no primitive applied cleanly:
1. **Contact-row `<Link>`** — a full-row navigation link, matching the existing row-link convention already used by `StockTable.tsx`/`ProductTable.tsx`/`SalesTable.tsx`.
2. **The `<ul>` group wrapper** — shape-matches a table wrapper (zero padding, per-row `px-4 py-3`, `divide-y`), not `Card` — `Card`'s padding model (`p-4`/`p-3`) has no zero-padding variant. Matches the established "table wrappers stay hand-rolled" precedent.
3. **The "no longer available" inline flag** — doesn't byte-match `Badge`'s classes (no background/padding/rounding). Matches the `ProductTable.tsx` status-pill precedent: not a pure mechanical swap, stays raw.

Two more exclusions inside the touched files, both deliberate:
4. **`ThreadView.tsx`'s "← Messages" back link** — the established colored-text-link pattern, same category Phase 40.1 named for Edit/Delete/View links.
5. **`ThreadView.tsx`'s peer-name `<h1>`** (name + nested role `<span>`) — caught by the final whole-branch review as an undocumented exclusion, now recorded in TD-6: `PageHeader`'s `title` prop is typed `string` and can't hold the compound name+role content, and its hardcoded `text-xl` would have changed this element's existing `text-lg`.

`FormSection` and `StatSummary` don't apply anywhere in this module (no field-pair grid, no stat to summarize) — same as Phase 40's own precedent that not every primitive fits every module.
